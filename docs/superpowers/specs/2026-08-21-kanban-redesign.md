# Kanban Redesign — Three-View Board

**Date:** 2026-08-21  
**Status:** Spec  
**Scope:** Replace JSON-backed single-board kanban with SQLite-backed multi-board + Markdown export + HTML status page + TUI widget

---

## Context

The current kanban (491 lines, `extensions/kanban.ts`) uses a JSON file (`~/.waywiser/kanban.json`) for state. Problems:
- Race condition: two concurrent saves = last-write-wins (subagent reports lost)
- Single global board — no project separation
- No human-readable export (only visible through TUI or tool)
- Inconsistent with the rest of waywiser (memory, cron, goals all use SQLite)

## Architecture

```
                    ┌──────────────┐
                    │  waywiser.db │  ← single source of truth
                    │  boards +    │     (same DB as memory, cron, goals)
                    │  cards       │
                    └──────┬───────┘
                           │  debounced regeneration on mutation
            ┌──────────────┼──────────────┐
            │              │              │
    ┌───────▼──────┐ ┌────▼─────┐ ┌──────▼──────┐
    │  board.html  │ │ BOARD.md │ │   TUI       │
    │  browser tab │ │ any editor│ │ terminal    │
    │  rich view   │ │ durable  │ │ operate     │
    └──────────────┘ └──────────┘ └─────────────┘
```

All three views are READ-ONLY projections. Operations happen through:
- **Agent conversation** (natural language → kanban tool)
- **TUI commands** (`/kanban new`, `/kanban done K3`)
- **Future:** standalone CLI (`waywiser board done K3` without running the agent)

## Phase 1 — SQLite Migration + Markdown Export + HTML Status Page

### 1.1 Schema (in waywiser.db)

```sql
CREATE TABLE IF NOT EXISTS boards (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    description TEXT,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    archived INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS cards (
    id TEXT PRIMARY KEY,
    board_id TEXT NOT NULL DEFAULT 'default',
    title TEXT NOT NULL,
    type TEXT NOT NULL DEFAULT 'task',
    status TEXT NOT NULL DEFAULT 'todo',
    priority TEXT NOT NULL DEFAULT 'med',
    assignee TEXT,
    block_reason TEXT,
    notes TEXT,
    report TEXT,
    due TEXT,
    worker_child TEXT,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

**Deliberately excluded (per audit):**
- `parent_id` — no subtask hierarchy (YAGNI; flat cards, use notes for grouping context)
- `tags` — type + priority + board_id already categorize; tags is a fourth axis nobody will search
- `position` — sort is computed (priority × overdue × due × id), not stored
- `color` on boards — decided at render time, not data
- `scheduled` status — cron handles scheduling

**Card types:** `task` | `idea` | `bug` (no `note` — memory system handles notes)

**Statuses:** `todo` | `doing` | `review` | `done` | `blocked` (5, down from 6 — removed `scheduled`)

**Priorities:** `low` | `med` | `high` | `critical`

### 1.2 Migration from JSON

On extension load, if `~/.waywiser/kanban.json` exists:
1. Read the JSON file
2. Ensure a `'default'` board exists in the DB
3. For each card in JSON: INSERT into cards table (map old fields to new schema)
4. Rename `kanban.json` → `kanban.json.migrated` (keep as backup, don't delete)
5. Log migration to stderr

Migration is idempotent: skip if `kanban.json` doesn't exist or cards already exist in DB.

### 1.3 Operations (backward compatible)

All existing ops preserved. Return type unchanged: `{ ok: boolean; msg: string; state?: BoardView }`.

The `BoardView` type replaces the old `Board` — it's a computed view, not the raw DB:

```typescript
interface BoardView {
    boardId: string;
    boardName: string;
    cards: CardRow[];
}
interface CardRow {
    id: string; board_id: string; title: string; type: string;
    status: string; priority: string; assignee?: string;
    block_reason?: string; notes?: string; report?: string;
    due?: string; worker_child?: string;
    created_at: string; updated_at: string;
}
```

Every mutation function:
1. Operates on SQLite (prepared statements, no full-board load)
2. Returns the result
3. Calls `scheduleRefresh()` which debounces the Markdown + HTML regeneration (500ms)

### 1.4 Markdown Export

**Path:** `~/.waywiser/boards/<board-id>.md`

**Format:**

```markdown
<!-- generated by waywiser — edits will be overwritten on next board change -->
# Board: Default

> 3 open · 1 overdue · 2 done

## ⚡ Doing
- [ ] **K3** Implement hero section `high` `due:Aug 25` → subagent
  > Report: header done, need images

## 📋 Todo
- [ ] **K5** Write about page copy `med` `due:Aug 30`
- [ ] **K7** SEO audit `low` 💡idea

## 🔴 Blocked
- [ ] **K1** Deploy to production `high`
  > waiting for DNS access

## ✅ Done
- [x] ~~K2 Set up Astro~~ · Aug 20
- [x] ~~K4 Configure CI~~ · Aug 21
```

Rules:
- Header warning: `<!-- generated by waywiser — edits will be overwritten -->`
- Sections only appear if they have cards (no empty "## Blocked" with no cards)
- Done section collapsed: title + date only (no notes/report)
- Non-done sections show: priority badge, due date, assignee, type icon for non-task (💡idea, 🐛bug)
- Notes shown as blockquote `> ...` (first 200 chars)
- Report shown as blockquote `> Report: ...` (first 200 chars)
- Overdue cards get `⚠️OVERDUE` marker

### 1.5 Live Board Dashboard (HTTP Server)

**URL:** `http://localhost:7749/` (port configurable via `~/.waywiser/board-server.json`)

The kanban extension starts a tiny HTTP server (Node.js `http.createServer`, zero deps) bound to
`127.0.0.1` on extension load. The server serves a self-contained single-page app and a REST API.
All localhost, zero internet, fully sovereign.

**Two modes:**
- **Waywiser running** → `http://localhost:7749/` serves the live interactive board (full CRUD + real-time SSE)
- **Waywiser NOT running** → `~/.waywiser/board.html` is a static snapshot generated on last mutation (read-only fallback)

#### 1.5.1 REST API

All endpoints return JSON. All mutations broadcast an SSE event.

```
GET    /api/boards                → [{ id, name, description, cardCount, overdueCount }]
POST   /api/boards               → { id, name, description }  body: { name, description? }
PUT    /api/boards/:id            → { id, name, description }  body: { name?, description? }
DELETE /api/boards/:id            → { ok: true }

GET    /api/cards?board=default   → [CardRow]  (filter by board, or all if omitted)
POST   /api/cards                 → CardRow    body: { title, board_id?, type?, priority?, due? }
PUT    /api/cards/:id             → CardRow    body: { title?, status?, priority?, type?, due?, notes?, assignee?, block_reason? }
DELETE /api/cards/:id             → { ok: true }

GET    /events                    → SSE stream (text/event-stream)
                                    Events: card_created, card_updated, card_deleted, board_changed
                                    Data: JSON of the affected entity
```

**Security:**
- Bound to `127.0.0.1` only (not `0.0.0.0`) — inaccessible from network
- No auth needed (localhost = trusted, same as pi itself)
- CORS: `Access-Control-Allow-Origin: *` (allows file:// and any local origin)
- XSS: all card data JSON-serialized via API, rendered by client-side JS with textContent (not innerHTML)

#### 1.5.2 SSE Real-Time Events

```
GET /events HTTP/1.1

HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

event: card_updated
data: {"id":"K3","status":"done","title":"Implement hero"}

event: board_changed
data: {"boardId":"default","action":"card_moved"}
```

Every mutation (from TUI, tool, or API) broadcasts to all connected SSE clients. The browser
auto-reconnects on disconnect (EventSource standard behavior).

Served at `GET /` — a single self-contained HTML page (all CSS + JS inline, zero external deps).

**CRUD interactions:**

| Action | UI | API call |
|--------|-----|----------|
| Add card | Click [+] on column header → inline form (title, type, priority, due) | POST /api/cards |
| Edit card | Click [✎] → expand card with editable fields | PUT /api/cards/:id |
| Delete card | Click [×] → confirm dialog | DELETE /api/cards/:id |
| Move card | Drag card to another column (HTML5 Drag & Drop API) | PUT /api/cards/:id {status} |
| Quick-done | Click card checkbox | PUT /api/cards/:id {status:"done"} |
| Add board | Click [+ Board] → name prompt | POST /api/boards |
| Switch board | Click board tab | Client-side filter (no API call) |
| Unblock | Click [▶] on blocked card | PUT /api/cards/:id {status:"todo", block_reason:null} |

**Card rendering:**
- Priority color: critical=red, high=orange, med=blue, low=gray
- Type icon: task=none, idea=💡, bug=🐛
- Overdue: red border + "⚠️ OVERDUE" badge
- Assignee: shown as "→ name"
- Click card to expand: shows notes (editable), report (read-only), timestamps
- Worker in-flight indicator: pulsing border + "⏳ subagent working..."
- Expand/collapse done column (collapsed by default, shows count)

**Real-time:**
- SSE connection to `/events`
- On any event → re-fetch affected card/board, update DOM (no full page reload)
- Connection status indicator: `● Connected` / `○ Disconnected (retrying...)`
- Offline fallback: if server unreachable, show static snapshot from last fetch

**Design:**
- Dark/light theme (CSS `prefers-color-scheme` + manual toggle, persisted in localStorage)
- Responsive: 4 columns on desktop, 2 on tablet, 1 on mobile
- Smooth drag-and-drop with drop-zone highlighting
- Inline editing (click title to edit, press Enter to save, Escape to cancel)
- Minimal animations (card slide on move, fade on delete)

#### 1.5.4 Static Snapshot Fallback

On every mutation (debounced 500ms), also write `~/.waywiser/board.html` — a STATIC version of the
board with all current data baked in, no JS API calls. This file is readable when waywiser isn't
running. It includes a banner: "⚠️ Static snapshot — start waywiser for the live board at localhost:7749"

#### 1.5.5 Startup / Shutdown

- **Extension load:** start HTTP server, log port to stderr: `waywiser/board: live at http://localhost:7749/`
- **`/kanban open`** command: opens the URL in the default browser (`xdg-open` on Linux, `open` on macOS)
- **`session_shutdown`:** close the HTTP server gracefully
- **Port conflict:** if 7749 is taken, try 7749+1, +2, ... up to +10. Log the actual port.

### 1.7 Debounced Regeneration

```typescript
let refreshTimer: ReturnType<typeof setTimeout> | undefined;
function scheduleRefresh(): void {
    if (refreshTimer) clearTimeout(refreshTimer);
    refreshTimer = setTimeout(() => {
        refreshTimer = undefined;
        regenerateMarkdown(activeBoardId);
        regenerateHtml(); // all boards in one file
    }, 500);
}
```

Every mutation calls `scheduleRefresh()`. Ten rapid mutations → one regeneration after 500ms of quiet.

### 1.8 Session-Start Board Injection

On `session_start`, inject a summary of open cards into the system prompt (after soul, before memory digest):

```
[Kanban — 3 open tasks]
K3 [doing/high] Implement hero section (OVERDUE since Aug 25) → subagent
K5 [todo/med] Write about page copy (due Aug 30)
K1 [blocked/high] Deploy to production — waiting for DNS
```

This replaces the TUI widget for the model — the model sees the board state in its system prompt.

## Phase 2 — Multi-Board Operations

### 2.1 Board Management Commands

```
/kanban boards                    → list all boards (name, card count, overdue count)
/kanban board <name>              → switch active board (create if not exists)
/kanban board create <name> [description]
/kanban board archive <name>      → hide from tabs/listing, keep data
/kanban board delete <name>       → permanent delete (requires confirm)
```

### 2.2 Active Board State

Stored per-session (not persisted across restarts):

```typescript
let activeBoardId = "default";
```

On `session_start`: if the cwd matches a known project path, auto-switch to that board. Otherwise, default.

### 2.3 Tool Parameter Addition

Add `board` optional parameter to the kanban tool:

```typescript
board: Type.Optional(Type.String({ description: "Board id (default: active board)" }))
```

Allows: `kanban action=new title="fix login" board=website`

### 2.4 Cross-Board Operations

```
/kanban move K3 doing --board website    → move card to different board + status
/kanban search <query>                    → FTS across all boards
```

### 2.5 HTML Update

Board tabs become clickable. Each tab shows its board's columns. Stats bar updates per active tab.

### 2.6 Markdown Update

One `.md` file per board: `~/.waywiser/boards/website.md`, `~/.waywiser/boards/default.md`.

## Phase 3 — Notification Digest Integration

### 3.1 Morning Digest

A cron job (created on first kanban use, user can disable):

```
Schedule: 0 9 * * 1-5  (weekdays at 9am, respects quiet hours)
```

Fires → agent checks the board → sends via notify:

```
📋 Waywiser Daily Board

3 open tasks · 1 OVERDUE · 1 blocked
⚠️ K3 Implement hero section — OVERDUE since Aug 25
🔴 K1 Deploy to production — blocked: DNS
📅 K5 Write about page copy — due in 9 days

Board: ~/.waywiser/board.html
```

### 3.2 Event-Driven Notifications

Triggered by board events, not cron:

| Event | Notification |
|-------|-------------|
| Card becomes overdue | `⚠️ K3 is now overdue (was due Aug 25)` |
| Subagent completes | `K3 worker finished — report filed, card → review` |
| All cards done on a board | `🎉 Board "website" — all tasks complete!` |

**Implementation:** Check overdue status on each `session_start` and after each mutation. Compare against a `last_overdue_notified` timestamp per card to avoid repeat notifications.

### 3.3 Tool Integration

Add kanban awareness to the notify tool description so the model knows it can combine them:

> "When a kanban card becomes overdue or a subagent finishes, use the notify tool to inform the user."

This is a PROMPT instruction, not code — the model decides when to notify based on context.

## Implementation Constraints

1. **Single file:** The kanban extension stays as one file (`extensions/kanban.ts`) + one HTML template helper. No new dependencies.
2. **Schema in state.ts:** The CREATE TABLE statements go in `db_()` alongside memories, cronjobs, goals (same migration pattern).
3. **Backward compatible:** All existing `/kanban` subcommands and tool actions work identically. New features are additive.
4. **Test coverage:** Every op tested against an isolated DB (same pattern as existing kanban tests). HTML/Markdown generation tested for correctness (contains expected cards, escapes HTML entities).
5. **XSS:** Every interpolated value in the HTML template MUST be escaped via a `escHtml()` helper. No raw interpolation.
6. **Debounce:** Markdown + HTML regeneration debounced at 500ms. Never inline in the mutation path.
7. **Migration:** JSON → SQLite is one-time, idempotent, non-destructive (renames, doesn't delete).
