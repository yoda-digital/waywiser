AgentLoop

/// Core agent cycle: prepare context → send to model → process response.
#[async_trait]
pub trait AgentLoop: Send + Sync {
    /// Build the context window for the next model call.
    async fn prepare(&self, session: &SessionState) -> Result<PreparedContext, WaywiserError>;

    /// Send prepared context to the inference backend, streaming tokens back.
    async fn execute(
        &self,
        ctx: PreparedContext,
        backend: &dyn InferenceBackend,
        cancel: CancellationToken,
    ) -> Result<ExecutionResult, WaywiserError>;

    /// Apply the model's response: persist records, enqueue follow-ups, run tools.
    async fn finalize(
        &self,
        result: ExecutionResult,
        session: &mut SessionState,
        store: &dyn SessionBackend,
    ) -> Result<FinalizeOutcome, WaywiserError>;
}

#[derive(Debug)]
pub enum FinalizeOutcome {
    /// Turn complete, no pending work.
    Done,
    /// Model requested tool calls; loop must execute them and re-enter.
    ToolCallsPending(Vec<ToolCall>),
    /// Model requested a follow-up turn.
    FollowUp,
    /// Steering request arrived mid-turn; re-prepare.
    Steered(SteerRequest),
    /// Abort requested.
    Aborted,
}

Key Behaviors

  • The loop drains the lane queue after every FinalizeOutcome::Done: pending_steer > pending_follow_up > next_run > deferred (priority order).
  • Steer requests arriving during Executing are queued, not applied immediately.
  • Recovery attempts up to 3 times with escalating repair: (1) re-read from store, (2) rebuild lane from records, (3) truncate corrupted tail.
  • All state transitions are logged as OperationRecord entries before the transition occurs (write-ahead).

Error Types

Uses WaywiserError::SessionNotFound, SessionCorrupted, CompactionFailed.

Testing

Conformance suite (component 7) drives all agent loop tests. Additionally: property tests for reducer state machine (no invalid transition reachable), fuzz OperationRecord deserialization.

Implementation Notes

  • WAL journal mode for concurrent reads during writes.
  • Single writer, multiple readers via r2d2 connection pool.
  • Schema migrations via embedded SQL files with version tracking table.
  • Session state serialized as CBOR blobs for lanes/entries; records stored row-per-record for query.
  • All writes within a single SQLite transaction per save_session call.

Kotlin side

// Repository bridging Rust events to Compose StateFlow.
class WaywiserRepository(private val runtime: WaywiserRuntime) {

    private val _events = MutableSharedFlow<RuntimeEvent>(
        extraBufferCapacity = 64,
        onBufferOverflow = BufferOverflow.DROP_OLDEST
    )
    val events: SharedFlow<RuntimeEvent> = _events

    private var pollJob: Job? = null

    fun startPolling(scope: CoroutineScope) {
        pollJob = scope.launch(Dispatchers.IO) {
            while (isActive) {
                try {
                    val event = runtime.pollEvent() ?: continue
                    _events.emit(event)
                } catch (e: WaywiserException) {
                    _events.emit(RuntimeEvent.Error(e.code, e.message ?: "unknown"))
                }
            }
        }
    }

    fun stopPolling() { pollJob?.cancel() }

    suspend fun sendMessage(content: String) = withContext(Dispatchers.IO) {
        runtime.sendMessage(content)
    }

    suspend fun cancel() = withContext(Dispatchers.IO) {
        runtime.cancel()
    }
}

Mandatory FFI Discipline

  • std::panic::catch_unwind wraps EVERY UniFFI-exported function. CI lint (clippy custom lint or build script) fails the build if any exported fn lacks it.
  • Cargo.toml: panic = "unwind" (never "abort").
  • Megazord pattern: single libwaywiser.so containing all Rust crates.
  • Kotlin callbacks (if any) use weak references; uniffiIsDestroyed checked before invoking.

Testing

Architecture

// ViewModel survives config changes. Process death → rebuild from SQLite.
class ConversationViewModel(
    private val repo: WaywiserRepository
) : ViewModel() {

    private val _uiState = MutableStateFlow(ConversationUiState())
    val uiState: StateFlow<ConversationUiState> = _uiState.asStateFlow()

    init {
        repo.startPolling(viewModelScope)
        viewModelScope.launch {
            repo.events.collect { event ->
                _uiState.update { state -> state.reduce(event) }
            }
        }
    }

    fun sendMessage(text: String) {
        viewModelScope.launch { repo.sendMessage(text) }
    }

    fun cancel() {
        viewModelScope.launch { repo.cancel() }
    }

    override fun onCleared() {
        repo.stopPolling()
        // Runtime.shutdown() called by Application.onTerminate or service unbind
    }
}

data class ConversationUiState(
    val messages: List<UiMessage> = emptyList(),
    val isStreaming: Boolean = false,
    val pendingText: String = "",
    val error: String? = null,
)

Key Behaviors

  • Inference token stored in Android Keystore, retrieved at Runtime init (§46).
  • System.loadLibrary("waywiser") in Application.onCreate.
  • Process death: WaywiserRuntime.new(config) re-reads all state from SQLite. No SavedStateHandle needed for Rust state.
  • Configuration change (rotation): ViewModel persists, Rust runtime unaffected.
  • minSdk = 26 (Android 8.0), targetSdk = 36 (Android 16).

P0 Acceptance Criteria

  1. User types a question in Compose UI; it reaches the Rust agent loop via the FFI bridge.
  2. Rust agent loop assembles context (identity + session history + tool definitions) and sends to Qwen3.8-27B via the Ollama OpenAI-compatible endpoint.
  3. Streamed text deltas display in the Compose conversation view in real time.
  4. Model proposes a tool call; the permission service authorizes it; the tool executes against one real Android capability (e.g., device.battery_status); the result returns to Qwen; the final answer displays.
  5. Session state (lanes, entries, records) is persisted to SQLite and survives: (a) Activity recreation via rotation, (b) process death via system kill + relaunch.
  6. Steering: user sends a steer request mid-turn; the agent loop drains it after the current turn completes and re-enters with the steer content.
  7. Abort: user cancels mid-stream; inference is cancelled, partial result discarded, session state remains consistent.
  8. Model manifest verification: on startup, the runtime checks the Ollama model identity matches expectations; a mismatch emits ModelMismatch error.
  9. Thinking budget: interactive turns default to ReasoningEffort::Medium, not XHigh.
  10. Conformance suite: all fixtures pass for both Rust and TypeScript runners (session CRUD, lane operations, compaction, recovery, queue semantics).
  11. Soak test: 4-hour continuous conversation (scripted) with no JNI global reference leaks, no memory growth beyond 50MB above baseline, no Rust panics reaching the Android process.
  12. CI pipeline: cargo test, cargo clippy (including catch_unwind lint), Android instrumented tests, and conformance suite all green.
